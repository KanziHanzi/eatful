# Session Gist - 2026-03-03

## What Changed

- Reworked project code style documentation into a clearer, stricter baseline.
- Replaced `conventions.md` with a canonical "Eatful Code Style" guide.
- Expanded style guidance around formatting, imports, React patterns, and quality checks.

## New Code Style Baseline

- Prettier is authoritative (single quotes, trailing commas, 2-space indentation, 120 width, no bracket spacing).
- Arrow-function-only policy remains for components, handlers, and utilities.
- Import grouping is now explicit: external, absolute internal (`src/*`), then relative.
- Prefer guard clauses/early returns over deep nesting.
- Route files in `app/*` stay thin; feature logic remains in `src/*`.

## Quality Expectations

- Always run `npm run lint` before handoff.
- Run `npx tsc --noEmit` when modifying types, storage, or wider data flow.

## Memory Update

- Updated `docs/agent-memory.md` so future sessions treat `conventions.md` as the source of truth for code style.
- Added a strict architecture rule: never use third-party libraries directly in screens/components; always access them through custom hooks (or adapter utils where appropriate).
- Added a screen architecture rule: avoid prop drilling in screens; use composition and screen-scoped context to share state/actions between child components.
- Added placement rule: screen-scoped context providers/hooks live in a local `hooks/` folder inside each screen directory.

## Implementation Applied to Existing Code

- Refactored `src/screens/Diary/Diary.tsx` to composition-first structure with `DiaryProvider` + `DiaryContent`.
- Added screen context in `src/screens/Diary/hooks/useDiaryContext.tsx` and removed heavy prop drilling to child components.
- Updated `DiaryHeader`, `DiaryGridItem`, `AddEntryModal`, and `EntryDetailModal` to consume screen context directly.
- Wrapped camera capture integration in `src/hooks/useCameraCapture.ts` (Expo Image Picker no longer used directly in screen/component code).
- Added app-level wrapper components for media/icons (`src/components/AppImage`, `src/components/AppIcon`) and switched diary components to use them.
- Extended wrapper enforcement to app layout: `app/_layout.tsx` now uses `useNavigationTheme`, `AppThemeProvider`, `AppRouterStack`, and `AppStatusBar`.
- Added `src/bootstrap/reanimated.ts` to encapsulate reanimated side-effect import away from route/component files.
- Validation passed: `npm run lint` and `npx tsc --noEmit`.

## State Ownership Follow-up

- Moved theme/palette-derived values out of screen context and back into consuming components (`Diary`, `DiaryGridItem`, `AddEntryModal`, `EntryDetailModal`).
- Reaffirmed rule in docs: local state stays local; context is only for cross-component shared state within a screen.
